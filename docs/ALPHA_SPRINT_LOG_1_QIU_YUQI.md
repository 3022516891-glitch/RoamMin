## 三、现有主流程核对

### 已具备的代码路径

1. 注册、登录及会话恢复：`frontend/src/api/auth.ts`、`frontend/src/store/authStore.ts`。
2. 创建行程与个人行程列表：`frontend/src/pages/MyHomePage.tsx`。
3. 搜索用户：`frontend/src/components/UserSearch.tsx`。
4. 邀请成员、获取成员列表：`frontend/src/api/social.ts` 与 `MyHomePage.tsx` 中的成员面板。
5. 后端权限校验：`backend/src/main/java/com/minroamer/trip/TripService.java`，只有 Owner 可以邀请成员，重复邀请、自邀和非成员访问均有校验。
6. 自动化回归：`frontend/scripts/verify-user-module.cjs`。

### 自动化脚本中的关键断言

- 注册第二个临时账号并完善昵称；
- 主账号创建“福州街巷漫游”；
- 第二个账号创建并公开另一条行程；
- 第二个账号邀请主账号加入行程；
- 主账号进入“参与的行程”，等待目标行程标题出现；
- 同时检查个人空间的发布、收藏、搭子帖和参与行程数量。

这说明主流程所需接口与页面已经形成闭环，11 月 23–24 日的重点是使用统一测试数据库做一次真实双账号回归，而不是重新设计接口。

## 五、问题与处理

1. **依赖目录未正确生成。** 初次检查时，pnpm 受到仓库内独立 E 模块 workspace 配置影响，没有给主 `frontend` 生成依赖目录，导致图标和国际化包缺失。改为对主前端单独安装依赖后，TypeScript 检查通过。
2. **Vite 构建脚本策略。** pnpm 安全策略忽略了 esbuild 的安装脚本，因此本次没有把主前端 Vite 生产构建记为通过；E 模块生产构建已通过。
3. **缺少 Java 工具链。** 当前验证机器没有 JDK/Maven，无法重新启动后端执行 Playwright 全流程。已有脚本与接口代码可作为准备完成的证据，但 11 月 23 日联调必须在具备 Java 17、Maven 3.9 的机器上补跑。
